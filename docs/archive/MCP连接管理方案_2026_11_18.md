# M6 MCP 连接管理方案（2026-11-18）

## 1. 目标

在能力管理页新增 **MCP** 分区（Tab 顺序：工具、技能、MCP、设置），提供：

1. 与工具页一致的筛选（全部 / 已连接 / 未连接）与搜索；
2. 「配置 MCP」弹窗：手动填写一个连接，或批量导入 `mcp.json`；
3. 列表右侧开关控制启用（热生效，无需重启），最左侧状态点显示连接状态；
4. 界面配置的 MCP 与 Agent / 官方 Settings 配置的 MCP **是同一份配置**，互相可见、状态一致。

UI 一律复用 `@deepseek-ai/dsh-client-ui-primitives`（Modal、Switch、StateDot、Pill、Input、SegmentedControl、Button、Tag、Tooltip、图标）。该包是 Web 前端静态资源（seed 模块白名单），只能按名字 require，不得打包。

## 2. 事实核查（0.2.2-rc.3）

| 旧项目做法（`dsh-visual-workflow/src/host/mcp/registry.ts`） | 现状 | 结论 |
|---|---|---|
| 在 profile `cordis.patch.yml` 里以 `@deepseek-ai/dsh-mcp-client` 行托管每台服务器 | 改为由官方 `@deepseek-ai/dsh-mcp-manager` 统一治理 `config.servers` | **失效**：自写 patch 不会触发 Loader 对账，且与 Settings 不是同一份配置 |
| 停用 = 另写 `- id: mcp-x / disabled: true` | 条目字段 `enabled: false`（保留条目、卸载实例） | 失效 |
| 命令整行 + Windows `cmd.exe /d /c` 包装 | MCP SDK 仍是非 shell spawn，包装逻辑仍然必要 | **仍适用**（移植为纯函数） |
| 手工 YAML 托管区解析 / 渲染 / 原子写 | 由 `ctx.configEditor.edit(entry, change)` 完成（与 Settings 同源） | 失效，改用官方写路径 |

官方契约（只读核查 `dsh-mcp-manager` / `dsh-mcp-client` / `dsh-config-editor` 源码）：

- `ctx.mcpManager.list(): McpManagedServerView[]` → `{ name, configured, status }`，`status` 含 `connected(toolCount)` / `connecting` / `reconnecting` / `waiting-credentials` / `failed(reason)` / `disabled` / `closed`；
- `ctx.mcpManager.config.servers` 是 `Volatile<Record<name, entry>>`，`get()` 给出**未展开模板**的条目（`transport/command/args/env/cwd/url/headers/enabled`）；
- 写入只经 `ctx.configEditor`：`entries()` 找到 `id === 'mcp-manager'` 的 Loader 条目，`edit(entry, current => next)` 写 profile patch 并让 Loader 热对账（`loader/volatile-update` → manager 重新对账）。官方 Settings 走同一条路。
- 条目校验口径：`serverName` 必须匹配 `[A-Za-z0-9_-]{1,32}`；stdio 必须有 `command`，且不得带 `url`/`headers`；streamable-http 必须有 `url`，且不得带 `command`/`args`/`env`/`cwd`。

**因此本功能不持有任何 MCP 配置副本**：读 `mcp-manager`，写 `config-editor`，与 Agent 配置天然同源。

## 3. 数据流

```
写入：浏览器弹窗/开关 → POST /capability-manager/api/mcp
      → host 纯函数校验/变换（servers 映射）
      → ctx.configEditor.edit(mcp-manager 条目)
      → Loader 热对账 → dsh-mcp-manager 增/删/停/重建实例
读取：ctx.mcpManager.list()（状态）+ mcpManager.config.servers.get()（条目）
      → 纯函数合并成 McpServerView[]
      → GET /capability-manager/api/mcp → 列表（连接状态打开分区时轮询）
```

不在 `SnapshotResponse` 里携带 MCP：连接状态需要秒级刷新，混进能力快照会让 2.5s 轮询拉全量能力目录。

## 4. 契约（`src/shared/mcp.ts` + `src/shared/api.ts`）

- `McpTransport = 'stdio' | 'streamable-http'`
- `McpState = 'connected' | 'connecting' | 'reconnecting' | 'waiting-credentials' | 'failed' | 'closed' | 'disabled'`
- `McpServerView { name, configured, registered, enabled, transport, target, state, toolCount?, lastError?, entry? }`
  - `registered: true` 表示条目由插件注册（只读，不可编辑/删除）
  - `target` 是列表摘要：stdio 的整行命令，或 http 的 URL
- `McpServersResponse { available, writable, servers, unavailableReason? }`
- `McpAction = save | toggle | delete | import`
- 新增错误码：`mcp-unavailable`、`mcp-invalid-entry`、`mcp-import-invalid`、`mcp-write-failed`、`mcp-unknown-server`
- 纯函数（两端共用）：`validateMcpForm`、`parseJsonObject`、`splitCommandLine`、`joinCommandLine`、`parseMcpJson`、`normalizeServerName`

## 6. 交互口径

- **筛选**：全部 / 已连接（`state === 'connected'`）/ 未连接（其余）。搜索命中名称与 `target`。
- **状态点**（`StateDot`）：`connected → done`（绿）、`connecting/reconnecting → ongoing`、`waiting-credentials → warning`、`failed → error`、`disabled/closed → idle`（灰）。
- **开关**：写 `enabled`。关 → 条目保留、实例卸载（状态 `disabled`）；开 → 立即挂载并进入 `connecting`，列表轮询反映连接结果。
- **编辑**：行内编辑按钮打开弹窗并回填；编辑时名称只读（改名即删除重建，不允许隐式发生）。
- **删除**：仅编辑弹窗底部，二次确认放在按钮文案里；注册条目与残留条目不可删除。
- **导入**：粘贴 `mcp.json` → 预览每台服务器（名称 / 传输 / 目标）→ 批量写入；同名条目覆盖并在预览中标注。
- **不可用**：未挂载官方管理器或缺 `configEditor` 时，分区显示原因与「如何启用」，不显示空列表冒充「没有服务器」。

## 8. 验收

- MCP 分区可新建 / 编辑 / 启停 / 删除 / 批量导入；
- 开关切换后状态点从灰变绿（或红并给出失败原因），无需重启；
- 用 Agent 或官方 Settings 添加的服务器出现在同一列表，名称、传输、状态一致；
- 中英文案齐全；测试全绿；`lib/` 构建产物不含被禁止打包的 `@deepseek-ai/*`。

## 9. 风险与边界

- `configEditor.edit` 依赖 Loader 条目存在与 fiber 可用；不可用时降级为只读列表并说明原因（不自行写 patch）。
- 轮询只在 MCP 分区挂载期间进行，避免与其他分区共享的 2.5s 写读节奏冲突。
- 环境变量 / 请求头中的 `${credential:…}` 原样保存与回显（官方口径：模板不展开），界面不声称能读出密钥值。
- 重建存在工具空窗（官方已知限制），界面不额外掩饰。
