# 能力管理插件 · 需求方案

> 本方案只描述**需求层面的行为契约**，不涉及代码结构、接口签名与实现选型。开发方案需结合 DSH 官方源码另出。术语沿用上一轮确认的概念清单。

---

## 一、方案定位与范围

### 1.1 定位

能力管理插件是一个**独立安装、独立加载的全局插件**，负责：

- 管理全局**能力池**（当前可被使用的能力全集，硬白名单）；
- 管理全局**初始配置**（启动时直接可用的能力子集，取自能力池）；
- 提供 `meta_search` 工具及其两种运行模式；
- 管理 MCP 服务器的创建、连接与配置；
- 承载自建工具 / 自建 Skill 的创建入口与热生效；
- 在检测到 Personal Agent 时，提供 Router / Worker 两个角色黑名单。

### 1.2 范围边界

- **全局性**：能力池、初始配置、索引、`meta_search`、MCP 连接、向量检索开关、自建能力热生效，均为全局生效。
- **唯一局部项**：Router / Worker 黑名单，且仅在 Personal Agent 插件已加载时出现。
- **不依赖 Personal Agent**：单独加载时，只有全局能力池与全局初始配置，无角色黑名单窗口，其余功能不变。
- **单向感知**：能力管理可感知 Personal Agent 是否存在；Personal Agent 不感知能力管理。

### 1.3 本方案不覆盖

- 自建 Consumer 是否必要（待分析官方源码，优先复用）；
- 角色判定的具体技术方式（开发时结合 Personal Agent 确定）；
- 管理页入口形态（开发时决定）；
- 热生效对已运行会话的刷新口径（开发时明确）；
- Skill 版本控制（后期规划）。

---

## 二、总体能力模型

```
能力 = 工具 + Skill
工具 = 官方自带工具 + 自定义工具 + MCP 工具
Skill = 官方 Skill + 用户自定义 Skill
```

系统对“能力是否可用”只有一条主链路：

```
能力池（硬白名单） → 角色黑名单（最高优先级排除） → 初始配置（池内子集） → 召回/直接使用
```

## 三、能力池需求

### 3.1 定义

能力池是**当前可被使用的能力全集**，包含工具和 Skill，是硬白名单。

### 3.2 行为契约

| 编号 | 需求 |
|---|---|
| CP-1 | 所有能力默认进入能力池。 |
| CP-2 | 用户可在管理界面将能力排除出能力池。 |
| CP-3 | 池外能力：不可调用、不可召回、不注入上下文。 |
| CP-4 | 能力池范围同时决定：`meta_search` 可召回范围、工具索引范围、Skill 索引范围、初始配置可选范围。 |
| CP-5 | `meta_search` 本身是工具，默认在能力池内；允许被排除出能力池。 |
| CP-6 | 能力池是全局的，不区分角色。角色差异只通过黑名单表达。 |

### 3.3 `meta_search` 被排除出能力池时

- 它不在能力池内，因此也不能被选入初始配置；
- 它既不可初始使用，也不可召回；
- Agent 只能依靠初始配置中的其他能力工作；
- 这是允许的合法配置，但管理界面应给出明确提示（见 13.4）。

## 四、初始配置需求

### 4.1 定义

初始配置是 **Agent 启动时默认直接拥有的能力子集**，只能从能力池中选取，包含初始工具和初始 Skill。

### 4.2 行为契约

| 编号 | 需求 |
|---|---|
| IC-1 | 初始配置只能从能力池中选能力，不能选池外能力。 |
| IC-2 | 初始配置包含初始工具和初始 Skill，不只是工具。 |
| IC-3 | 初始工具启动后无需召回即可直接使用。 |
| IC-4 | 初始 Skill 启动后无需召回即可直接使用，行为与官方正常 Skill 目录一致。 |
| IC-5 | `meta_search` 可被选入初始配置，也可不被选入；它不是常驻项、不是固定项。 |
| IC-6 | 初始配置允许只包含 `meta_search`；也允许 `meta_search` + 其他初始能力；也允许完全不包含 `meta_search`，只把其他工具和 Skill 列为初始能力。 |
| IC-7 | 初始配置是能力池的子集，不是独立于能力池的另一套管辖范围。 |
| IC-8 | 黑名单优先级高于初始配置：某能力即使在初始配置中，被该角色黑名单排除后，对该角色仍不可用。 |

### 4.3 最终启动直接能力

对某个 Agent（全局或某角色）：

```
启动直接能力 = 初始配置 ∩ (能力池 − 该角色黑名单)
```

全局时黑名单为空，即 `初始配置`。

## 五、`meta_search` 需求

### 5.1 定义

`meta_search` 是一个工具，接收关键词或名称组，召回能力池内的工具和 Skill。它受能力池与角色黑名单双重约束。

### 5.2 召回通道

| 通道 | 触发方式 | 是否依赖 embedding | 是否受向量开关影响 |
|---|---|---|---|
| 语义召回 | 关键词 | 是 | 是；仅开启向量检索时生效 |
| 正则精确召回 | 准确名称组，正则匹配，支持批量 | 否 | 否；永远存在 |

### 5.3 返回内容契约

| 召回对象 | 返回内容 |
|---|---|
| 工具 | 完整内容（schema / 参数描述），使 Agent 可直接调用。 |
| Skill | Skill 索引（`name + description`），不返回正文；正文由 `官方 skill 工具` 加载。 |

### 5.4 召回范围

```
召回范围 = 能力池 − 该角色黑名单
```

- 池外能力不参与召回；
- 黑名单排除的能力对该角色不参与召回；
- 召回结果进入官方会话存储（会话日志），成为 Agent 上下文的一部分；断电、重启后仍在，不需要重新召回。

### 5.5 去重需求

| 编号 | 需求 |
|---|---|
| MS-1 | `meta_search` 返回前执行**载荷级去重**。 |
| MS-2 | 比较对象：本次召回载荷 vs 上下文中已存在的**同类型载荷**。 |
| MS-3 | 判定标准：**原样逐字完全一致**才剔除；不做名称级、语义级或字段级模糊判重。 |
| MS-4 | 载荷类型：工具载荷 = 工具完整 schema；Skill 载荷 = Skill 索引（`name + description`）。 |
| MS-5 | 工具索引与工具完整 schema 不是同一载荷，不互相判重。 |
| MS-6 | Skill 索引与 Skill 正文不是同一载荷，不互相判重。 |
| MS-7 | 被剔除项不出现在返回值中。 |
| MS-8 | 去重目的：防止同一载荷被多次召回、重复占用上下文。 |

### 5.6 判重粒度说明

- 初始上下文只有工具索引时，`meta_search` 召回工具完整内容，**不算重复**，正常返回。
- Skill 索引已在上下文中时，`meta_search` 召回 Skill 索引，若与已有索引逐字一致，**剔除**，表现为召回数为 0。
- 两次召回列表中出现重复载荷，按同一规则剔除。

## 六、两种运行模式需求

### 6.1 模式 A：不启用向量检索（默认）

| 编号 | 需求 |
|---|---|
| MA-1 | 语义召回不生效，不需要 embedding 模型。 |
| MA-2 | 初始上下文常驻**工具索引**与 **Skill 索引**。 |
| MA-3 | `meta_search` 对工具：通过正则精确召回返回完整内容。 |
| MA-4 | `meta_search` 对 Skill：因 Skill 索引已常驻，返回载荷与上下文完全一致，被去重剔除，表现为召回数为 0。 |
| MA-5 | 非初始 Skill 仍可凭常驻 Skill 索引，直接通过 `官方 skill 工具` 加载正文。 |
| MA-6 | 正则精确召回永远存在，支持批量名称组。 |

### 6.2 模式 B：启用向量检索

| 编号 | 需求 |
|---|---|
| MB-1 | 语义召回生效；需联网下载 `bge-small-zh-v1.5` 模型，全局生效。 |
| MB-2 | 工具索引与 Skill 索引不需要初始常驻上下文。 |
| MB-3 | `meta_search` 可正常召回 Skill 索引；工具仍返回完整内容。 |
| MB-4 | 正则精确召回仍保留，与语义召回并存。 |
| MB-5 | 非初始 Skill 需先召回 Skill 索引，再通过 `官方 skill 工具` 加载正文。 |

### 6.3 开关需求

| 编号 | 需求 |
|---|---|
| SW-1 | 向量检索默认关闭。 |
| SW-2 | 启用需联网下载 `bge-small-zh-v1.5`；下载失败或未完成时，系统应保持关闭状态并提示。 |
| SW-3 | 开关全局生效。 |
| SW-4 | 开关只控制是否启用向量检索，不控制正则精确召回。 |

## 七、索引需求

### 7.1 工具索引

| 编号 | 需求 |
|---|---|
| TI-1 | 条目为 `name + 简短描述 + 副作用`。 |
| TI-2 | 范围是能力池内的工具，不包含 Skill。 |
| TI-3 | 仅在模式 A（不启用向量检索）下初始常驻上下文。 |
| TI-4 | 工具索引不是工具完整 schema，不构成直接调用工具的完整载荷。 |

### 7.2 Skill 索引

| 编号 | 需求 |
|---|---|
| SI-1 | 条目为 `name + description`。 |
| SI-2 | 范围是能力池内的 Skill。 |
| SI-3 | 仅在模式 A 下初始常驻上下文。 |
| SI-4 | Skill 索引不是 Skill 正文，不构成加载正文的完整载荷。 |

### 7.3 索引常驻的前置条件

索引常驻的目的是支撑 `meta_search` 的精确召回。若 `meta_search` 不在初始配置中（即启动时不可用），索引常驻将只占用上下文而不产生召回能力。建议需求定为：

- **模式 A 下，索引常驻的条件是：`meta_search` 在启动直接能力中。**
- 若 `meta_search` 不可用，则不注入索引，避免上下文浪费。

## 九、角色黑名单需求

### 9.1 出现条件

仅在检测到 Personal Agent 插件已加载时，管理界面出现 Router 黑名单与 Worker 黑名单两个独立配置窗口。未检测到时，两窗口不出现，其余功能不变。

### 9.2 行为契约

| 编号 | 需求 |
|---|---|
| BL-1 | 黑名单对象是能力（工具 + Skill）。 |
| BL-2 | 黑名单是**最高优先级**：无论能力是否在能力池内、是否在初始配置中，被某角色黑名单排除后，对该角色一律不可用、不可召回、不注入。 |
| BL-3 | 对另一角色和全局不受影响。 |
| BL-4 | 黑名单配置存储在能力管理插件；Personal Agent 侧不重复配置。 |
| BL-5 | MCP 服务器连接是全局的；黑名单不影响连接本身，只影响该服务器下的工具是否分配给某个角色。 |
| BL-6 | 角色判定方式开发时确定；能力管理需在运行时知道当前 Agent 是 Router 还是 Worker。 |

### 9.3 效果公式

对角色 R：

```
R 的可用能力 = 能力池 − R 黑名单
R 的启动直接能力 = 初始配置 ∩ (能力池 − R 黑名单)
R 的召回范围 = 能力池 − R 黑名单
```

## 十二、判定顺序与优先级契约（核心）

对任意一次“某能力是否可用于某 Agent”的判定，按以下顺序执行，**先命中先决定**：

```
第 1 步：角色黑名单判定（最高优先级）
    若能力 ∈ 当前角色黑名单 → 不可用、不可召回、不注入，结束。
    若未检测到 Personal Agent 或能力不在黑名单 → 进入第 2 步。

第 2 步：能力池判定（硬白名单）
    若能力 ∉ 能力池 → 不可用、不可召回、不注入，结束。
    若能力 ∈ 能力池 → 进入第 3 步。

第 3 步：初始配置判定（仅决定“启动是否直接可用”）
    若能力 ∈ 初始配置 → 启动直接可用。
    若能力 ∉ 初始配置 → 启动不可直接用，只能经 meta_search 召回后使用。

第 4 步：召回判定（仅对非初始能力或主动召回）
    召回范围 = 能力池 − 当前角色黑名单。
    meta_search 返回前执行载荷级去重，剔除与上下文同类型载荷逐字一致的项。

第 5 步：使用判定
    工具：初始工具直接调用；召回工具凭返回的完整 schema 调用。
    Skill：初始 Skill 直接可用；非初始 Skill 凭索引调用 官方 skill 工具 加载正文。
```

### 关键优先级说明

- **黑名单 > 能力池 > 初始配置**。
- 黑名单可排除能力池内能力，也可排除初始配置内能力。
- 能力池可排除初始配置候选，因为初始配置只能从池内选。
- 初始配置不改变能力池范围，只决定启动时哪些池内能力直接可用。

## 十三、管理界面需求

### 13.1 页面与窗口

| 模块 | 内容 |
|---|---|
| 工具管理 | 查看工具（官方/自定义/MCP）；引入或排除能力池；配置初始工具。 |
| Skill 管理 | 查看 Skill（官方/自定义）；引入或排除能力池；配置初始 Skill。 |
| MCP 管理 | 新建 / 连接 / 配置 MCP 服务器；手动键入或内置 Skill 辅助。 |
| 能力池配置 | 查看与调整能力池范围；查看当前池内工具与 Skill。 |
| 初始配置 | 从能力池中选择初始工具与初始 Skill；可勾选 `meta_search`。 |
| 向量检索设置 | 开关；启用时触发 `bge-small-zh-v1.5` 下载与状态展示。 |
| Router 黑名单 | 仅检测到 Personal Agent 时出现；从全局能力池中排除 Router 不需要的能力。 |
| Worker 黑名单 | 仅检测到 Personal Agent 时出现；从全局能力池中排除 Worker 不需要的能力。 |

### 13.2 配置真源

- 管理界面勾选结果存入插件配置，配置文件为真源。
- 后续大部分内容以配置文件为真源，界面只做展示与编辑入口。

### 13.3 界面一致性要求

- 初始配置候选列表只显示能力池内能力。
- 被黑名单排除的能力，在对应角色的初始配置候选中应标记为不可选或提示将被排除。
- `meta_search` 被排除出能力池时，初始配置中不可选；已在初始配置中的应提示失效。

### 13.4 配置风险提示

| 场景 | 提示 |
|---|---|
| `meta_search` 不在初始配置，但能力池中存在非初始能力 | 提示：这些非初始能力将无法被召回使用，除非后续通过其他方式暴露 `meta_search`。 |
| `meta_search` 被排除出能力池 | 提示：`meta_search` 不可用，Agent 只能依靠初始配置中的其他能力工作。 |
| 模式 A 下 `meta_search` 不可用 | 提示：工具索引与 Skill 索引将不注入，以节省上下文。 |
| 初始配置为空 | 提示：Agent 启动时无直接可用能力。 |
| 黑名单排除了初始配置中的能力 | 提示：该能力对该角色将不可用。 |

### 13.5 管理页入口

左侧栏入口，位于“插件”按钮下方，命名为：“能力管理”。（已决定）

## 十四、边界与异常场景需求

| 编号 | 场景 | 需求行为 |
|---|---|---|
| EX-1 | 能力池为空 | Agent 启动时无任何能力可用；`meta_search` 也不可用（若未在池内）。界面应提示。 |
| EX-2 | 初始配置为空 | Agent 启动时无直接可用能力；若 `meta_search` 也不可用，则完全无能力。界面应提示。 |
| EX-3 | `meta_search` 在池内但不在初始配置 | 启动时不可用；非初始能力无法召回；界面提示（见 13.4）。 |
| EX-4 | `meta_search` 被排除出能力池 | 不可用、不可召回；初始配置中不可选。 |
| EX-5 | 模式 A 下 `meta_search` 不可用 | 索引不注入（按 7.3 推导），避免上下文浪费。 |
| EX-6 | 向量检索开启但模型下载失败 | 保持关闭状态，提示失败原因；精确召回不受影响。 |
| EX-7 | MCP 服务器连接失败 | 连接全局失败；该服务器下工具不可用；不影响其他能力。 |
| EX-8 | MCP 工具被黑名单排除 | 连接仍全局保持；仅该角色不分配该工具。 |
| EX-9 | 自建工具/Skill 名称与已有能力冲突 | 需在创建时校验并提示；具体策略开发时定。 |
| EX-10 | 能力池排除某能力后，该能力已在初始配置中 | 初始配置中该项应失效并提示；实际启动能力按判定顺序第 2 步排除。 |
| EX-11 | 某能力被角色黑名单排除，但仍在初始配置中 | 对该角色启动时不生效；对另一角色和全局不受影响。 |
| EX-12 | 去重比较时上下文载荷被截断或规范化 | 按“原样逐字一致”判定；规范化口径开发时定，但不得放宽为名称级判重。 |

## 十六、验收标准（需求级）

1. 单独加载能力管理插件时，全局能力池与初始配置生效，无角色黑名单窗口。
2. 同时加载 Personal Agent 时，出现 Router / Worker 黑名单窗口，配置存储于能力管理插件。
3. 池外能力不可调用、不可召回、不注入上下文。
4. 初始配置只能从能力池选取；启动直接能力 = 初始配置 ∩ (能力池 − 角色黑名单)。
5. 模式 A 下：工具索引与 Skill 索引常驻；`meta_search` 对工具返回完整内容；对 Skill 因去重表现为召回数为 0；非初始 Skill 可经 `官方 skill 工具` 加载。
6. 模式 B 下：语义召回生效；`meta_search` 可召回 Skill 索引；精确召回仍存在。
7. 去重按载荷级、原样逐字一致执行；工具索引与工具完整 schema 不互相判重。
8. 黑名单最高优先级：可排除能力池内能力与初始配置内能力；不影响 MCP 连接本身。
9. 自建工具 / Skill 全局热生效，默认进能力池、默认不进初始配置。
10. 向量检索默认关闭；启用需下载 `bge-small-zh-v1.5`；失败时保持关闭并提示。
