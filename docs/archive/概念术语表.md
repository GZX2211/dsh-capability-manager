# 能力管理插件 · 概念清单

## 一、插件与作用域

**1. 能力管理插件**
独立安装、独立加载的全局插件，管理全局能力池与初始配置。不依赖 Personal Agent 即可工作。

**2. 全局生效**
能力池、初始配置、自建工具/Skill 热生效、MCP 连接、向量检索开关均为全局。插件本身没有“局部能力管理”。

**3. 局部生效**
唯一局部项是 Router 黑名单与 Worker 黑名单，且仅在检测到 Personal Agent 插件已加载时出现。

**4. Personal Agent 集成**
单向、可选：能力管理可感知 Personal Agent 是否存在；Personal Agent 不感知能力管理。未加载 Personal Agent 时，无角色黑名单窗口，其余功能不变。

**5. 自建 Consumer（待探究项）**
Skill 机制是否必须自建 Consumer，后续通过分析官方源码判断；优先复用官方体系。

---

## 二、能力模型

**6. 能力**
能力 = 工具 + Skill。后文凡称“能力”，均指这两类。

**7. 工具**
工具 = 官方自带工具 + 自定义工具 + MCP 工具。

**8. Skill**
Skill = 官方 Skill + 用户自定义 Skill。

---

## 三、能力池

**9. 能力池**
当前可被使用的能力全集，是硬白名单。包含工具和 Skill。

**10. 池外能力**
不可调用、不可召回、不注入上下文。

**11. 能力池默认状态**
所有能力默认进入能力池，可手动排除。排除后即成为池外能力。

**12. 能力池与初始配置的关系**
初始配置只能从能力池中选能力；初始配置是能力池的子集。

---

## 四、初始配置

**13. 初始配置**
Agent 启动时默认直接拥有的能力子集，从能力池中选取。包含初始工具和初始 Skill，不只是工具。

**14. 初始工具**
初始配置中被选中的工具，启动后无需召回即可直接使用。

**15. 初始 Skill**
初始配置中被选中的 Skill，启动后无需召回即可直接使用，行为与官方正常 Skill 目录一致。

**16. `meta_search` 在初始配置中的位置**
`meta_search` 本身是工具，属于能力池；可被选入初始配置，也可不被选入。它不是常驻项、不是固定项，是可选项。

**17. `meta_search` 被排除出能力池**
允许。此时它既不可初始使用，也不可召回；Agent 只能依靠初始配置中的其他能力工作。

---

## 五、`meta_search` 与召回

**18. `meta_search`**
一个工具，接收关键词或名称组，召回能力池内的工具和 Skill。受能力池与角色黑名单双重约束。

**19. 语义召回**
按关键词语义召回，需要 embedding 模型。默认关闭；开启需联网下载 `bge-small-zh-v1.5`，全局生效。

**20. 正则精确召回**
按准确名称组做正则匹配召回，支持批量召回。**永远存在**，不受向量检索开关影响。

**21. 召回返回内容**
- 工具：返回完整内容（schema/参数描述），使 Agent 可直接调用。
- Skill：返回 Skill 索引（`name + description`），不返回正文；正文由 `官方 skill 工具` 加载。

**22. 召回范围**
能力池 ∩ 角色黑名单排除后的剩余能力。池外能力不参与召回；黑名单排除的能力对该角色不参与召回。

**23. 召回结果进入上下文**
召回内容进入官方会话存储（会话日志），成为 Agent 上下文的一部分；断电、重启后仍在，不需要重新召回。

---

## 六、两种运行模式

**24. 不启用向量检索**
- 语义召回不生效，不需要 embedding。
- 初始上下文常驻**工具索引**与 **Skill 索引**。
- `meta_search` 对工具：精确召回完整内容。
- `meta_search` 对 Skill：因 Skill 索引已常驻，返回载荷与上下文完全一致，被去重剔除，表现为召回数为 0。
- 非初始 Skill 仍可凭常驻索引直接通过 `官方 skill 工具` 加载正文。

**25. 启用向量检索**
- 语义召回生效；精确召回仍保留，两种通道并存。
- 工具索引与 Skill 索引不需要初始常驻上下文。
- `meta_search` 可正常召回 Skill 索引；工具仍返回完整内容。
- 非初始 Skill 需先召回索引，再通过 `官方 skill 工具` 加载正文。

---

## 七、索引

**26. 工具索引**
条目为 `name + 简短描述`（需要自制工具索引表，开发时分析如何制作）。范围是能力池内的工具，不包含 Skill。关闭向量检索时初始常驻上下文。

**27. Skill 索引**
条目为 `name + description`。范围是能力池内的 Skill。关闭向量检索时初始常驻上下文。

**28. 索引与完整内容的区别**
工具索引不是工具完整 schema；Skill 索引不是 Skill 正文。索引用于让模型知道“有什么、大概做什么”，不构成直接调用工具或加载 Skill 正文的完整载荷。

---

## 八、Skill 加载

**29. `官方 skill 工具`**
官方工具，用于加载 Skill 正文并启用。初始 Skill 无需加载；非初始 Skill 在拿到 Skill 索引后，通过工具加载正文。

**30. 关闭向量检索时的 Skill 使用路径**
Skill 索引常驻 → 模型凭索引直接调用 `官方 skill 工具` 加载正文。`meta_search` 不返回 Skill 索引（去重），但 Skill 仍可使用。

**31. 启用向量检索时的 Skill 使用路径**
`meta_search` 召回 Skill 索引 → 模型调用 `官方 skill 工具` 加载正文。

---

## 九、去重

**32. 载荷级去重**
`meta_search` 返回前，将本次召回载荷与上下文中已存在的同类型载荷比较；**原样逐字完全一致**才剔除。剔除项不出现在返回值中。

**33. 载荷类型**
- 工具载荷 = 工具完整 schema/参数描述。
- Skill 载荷 = Skill 索引（`name + description`）。

**34. 去重边界**
工具索引与工具完整 schema 不是同一载荷，不互相判重；Skill 索引与 Skill 正文不是同一载荷，不互相判重。去重只防同一载荷被多次召回、重复占用上下文。

**35. 去重目的**
防止 `meta_search` 多次召回完全相同的工具或 Skill 索引，造成上下文浪费。

---

## 十、黑名单

**36. Router 黑名单 / Worker 黑名单**
仅在检测到 Personal Agent 插件时出现的两个角色级排除配置。配置存储在能力管理插件；Personal Agent 侧不重复配置。

**37. 黑名单对象**
排除的是能力（工具 + Skill）。

**38. 黑名单优先级**
最高优先级。无论能力是否在能力池内、是否在初始配置中，被某角色黑名单排除后，对该角色一律不可用、不可召回、不注入。对另一角色和全局不受影响。

**39. 黑名单与 MCP**
MCP 服务器连接是全局的；黑名单不影响连接本身，只影响该服务器下的工具是否分配给某个角色。

**40. 角色判定方式**
开发时结合 Personal Agent 插件情况确定；能力管理需要运行时知道当前 Agent 是 Router 还是 Worker，才能应用对应黑名单。

---

## 十一、创建与生效

**41. 自建工具**
通过内置“工具创建 Skill”让 Agent 制作工具，创建后全局热生效。

**42. 自建 Skill**
通过内置 Skill 创建，创建后全局热生效。

**43. MCP 管理**
新建/连接/配置 MCP 服务器，可手动键入配置，也可通过内置 Skill 让 Agent 配置或自建 MCP 服务；连接全局生效。

**44. 热生效范围**
自建工具/Skill 全局生效。当前已运行会话是否立即刷新，开发时需明确实现口径；需求上定为全局热生效。

**45. 后期规划**
Skill 版本控制。

---

## 十二、管理界面

**46. 管理界面包含**
- 工具管理：查看工具、引入/排除能力池、配置初始工具。
- MCP 管理：新建/连接/配置 MCP 服务器。
- Skill 管理：查看 Skill、引入/排除能力池、配置初始 Skill。
- 能力池配置：`meta_search` 可检索范围。
- 初始配置：从能力池中选择初始工具与初始 Skill，含是否选择 `meta_search`。
- 角色黑名单（仅检测到 Personal Agent 时）：Router / Worker 两个窗口。
